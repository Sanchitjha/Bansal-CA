# Deployment Guide

Backend → **Render** (`server/render.yaml` blueprint)
Frontend → **Vercel** (Next.js, root at `client/`)
Database → **MongoDB Atlas** (free tier is enough to start)

Deploy the backend first — the frontend needs its public URL.

---

## 0. One-time prerequisites

1. Push the latest `main` to GitHub. Render + Vercel deploy from the repo.
2. Create a **MongoDB Atlas** free cluster:
   - Create a database user with a strong password.
   - Network Access → allow `0.0.0.0/0` (or Render's egress IPs).
   - Copy the SRV connection string (looks like `mongodb+srv://<user>:<pass>@cluster0.xxxxx.mongodb.net/bansal_ca`).
3. Have accounts on <https://render.com> and <https://vercel.com>, both connected to your GitHub.

---

## 1. Deploy backend on Render

The repo already ships [`server/render.yaml`](server/render.yaml) as a Blueprint.

**Option A — via Blueprint (recommended):**
1. Render dashboard → **New → Blueprint** → pick this GitHub repo.
2. Render reads `server/render.yaml` and prompts for the `sync: false` secrets. Fill:

    | Variable              | Value                                                                                   |
    |-----------------------|------------------------------------------------------------------------------------------|
    | `MONGODB_URI`         | Your Atlas SRV string (add `/bansal_ca` at the end to name the DB)                       |
    | `CLIENT_URL`          | Leave blank for now; you'll fill this after Vercel deploy (step 2). Any value works to start. |
    | `SEED_ADMIN_EMAIL`    | e.g. `amit.bansal@aa.com`                                                                |
    | `SEED_ADMIN_PASSWORD` | Strong password — change immediately after first login                                  |

3. `JWT_SECRET` is auto-generated by Render. Don't set it manually.
4. Deploy. Render will `npm install && npm run build`, then `npm run start`.
5. When the service is live, hit `https://<your-service>.onrender.com/health` → should return `{"status":"ok"}`.
6. Copy the Render URL — you'll need it in step 2.

**Option B — manual Web Service (if you don't want Blueprint):**
- New Web Service → connect repo → Root Directory `server` → Build `npm install && npm run build` → Start `npm run start` → Add each env var from `render.yaml` by hand.

**Free-tier note:** Render's free web services sleep after 15 min of inactivity. First request after a nap takes ~30s to cold-start.

---

## 2. Deploy frontend on Vercel

1. Vercel dashboard → **Add New → Project** → import this GitHub repo.
2. **Root Directory: `client`** (crucial — the Next.js app lives in a subfolder).
3. Framework should auto-detect as **Next.js**. Build settings pick up [`client/vercel.json`](client/vercel.json).
4. Add one **Environment Variable** (all environments):

    | Variable                | Value                                                       |
    |-------------------------|-------------------------------------------------------------|
    | `NEXT_PUBLIC_API_URL`   | Your Render URL from step 1 (no trailing slash), e.g. `https://bansal-ca-backend.onrender.com` |

5. Deploy. Vercel will `next build` and give you a URL like `https://bansal-ca.vercel.app`.

---

## 3. Cross-wire CORS on the backend

Now that both URLs exist, close the loop:

1. Render dashboard → your service → **Environment** → edit `CLIENT_URL`.
2. Set it to your Vercel URL (no trailing slash), e.g. `https://bansal-ca.vercel.app`.
3. Manual deploy → **Deploy latest commit** (or wait for the auto-restart the env change triggers).

The backend's CORS is now scoped to your Vercel origin.

---

## 4. First login

After both services are up:

1. Open your Vercel URL, go to `/admin/login`.
2. Log in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` you set in step 1.
3. The backend seeds the admin user + role + demo services on first boot.

**Change the admin password immediately** through the admin UI (once that flow lands) or by removing the `SEED_ADMIN_PASSWORD` env var and re-seeding via a script.

---

## 5. Pre-deploy sanity checks

Before pushing to GitHub, run locally:

```bash
cd server && npm install && npm run build
cd ../client && npm install && npm run build
```

Both should exit clean. If not, fix locally first — Render/Vercel builds are slower to iterate on.

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Vercel login page loads but every API call returns CORS error | `CLIENT_URL` on Render not set to your Vercel origin. Update env, redeploy. |
| Vercel builds fail with "Cannot find module 'next'" | Root Directory not set to `client`. Vercel is trying to build from repo root. |
| Render build fails on `npm run seed` | Don't include seed as build step — it runs automatically on server start when DB is empty. |
| `/health` returns 502 on Render | Backend crashed on startup. Check Render → Logs. Common cause: bad `MONGODB_URI` or missing env var. |
| Login returns 400 "Invalid email or password" but creds look right | Case mismatch — email is lowercased on write. Try lowercase. |
| Frontend login succeeds but subsequent API calls 401 | JWT token not saved to localStorage. Check browser devtools → Application → Local Storage → `aa_token` should have a value. |
| Cold-start latency on first request | Render free plan puts service to sleep after 15 min idle. Upgrade to Starter plan ($7/mo) for always-on. |

## What NOT to commit

- `.env` (local secrets)
- `.env.local`
- Anything with real credentials

The `.env.example` files are the source of truth for which variables exist.
